สิ่งที่การแก้นี้น่าจะปลดล็อกไปด้วย — ก่อนหน้านี้ www และแบบไม่มี www ต่างก็ตอบ 200 ทั้งคู่ ไม่มี redirect ไม่มี canonical คือทุกหน้าของเว็บมีอยู่สองที่อยู่ ซึ่งเป็นสัญญาณเนื้อหาซ้ำที่ครอบทั้งเว็บ และน่าจะเป็นสาเหตุของการถูกปฏิเสธรอบก่อนหน้า — ตอนนี้หายไปแล้ว

ระหว่างทางมีจังหวะที่ rule ถูกตั้งเป็นแบบ Static (ชี้ปลายทางตายตัว) ทำให้ ทุก URL ไปโผล่หน้าแรกและ path หายหมด รวมถึง ads.txt ที่คืน HTML แทนไฟล์

ตอนตั้ง redirect ให้โดเมนใหม่ ต้องเลือก Dynamic เสมอ และตรวจ 4 อย่างเดิม — path · status 301 · query string · ไม่มี loop

🔴 วิธีแก้ · แก้ rule เดิมให้เป็น dynamic — 10 นาที ไม่ต้องแตะโค้ด

Cloudflare → Rules → Redirect Rules → เปิด rule ที่เพิ่งสร้าง แล้วแก้ให้เป็นแบบนี้

// เงื่อนไข
Hostname  equals  "gnjoy.in.th"

// การกระทำ — ต้องเลือก Dynamic ไม่ใช่ Static
Type      Dynamic
Expression concat("https://www.gnjoy.in.th", http.request.uri)
Status    301  Permanent Redirect
Preserve query string  ไม่ต้องติ๊ก

🔴 “Preserve query string” ต้องไม่ติ๊ก เมื่อใช้ http.request.uri

เพราะ http.request.uri มี query string รวมอยู่แล้ว (ต่างจาก http.request.uri.path ที่มีแต่ path) ถ้าติ๊กเพิ่มจะกลายเป็นต่อ query เข้าไปซ้ำอีกรอบ

ยืนยันด้วยการทดสอบจริงแล้ว — ยิง ?page=3&lang=th เข้าไปโดยที่ช่องนี้ไม่ติ๊ก query ตามไปครบถ้วนถูกต้อง

⚠️ เรื่อง POST ที่ Cloudflare ขึ้นเตือนไว้ในหน้าตั้งค่า — 301 จะเปลี่ยน POST เป็น GET และทิ้ง body ทิ้ง

สำหรับคนเปิดเว็บทั่วไปไม่มีปัญหา แต่ต้องตรวจว่า มีระบบภายนอกยิง POST มาที่ gnjoy.in.th (แบบไม่มี www) หรือไม่ — จาก CSP ของเว็บเห็นว่ามีการต่อกับ UniPin · Razer Gold · Freshworks ถ้า callback ของระบบจ่ายเงินตัวใดยิงมาที่โดเมนแบบไม่มี www จะพังเงียบ ๆ

วิธีตรวจ: ถามทีมที่ดูแลการเชื่อมต่อว่า URL ปลายทางที่ให้ผู้ให้บริการไว้เป็น www หรือไม่ · ถ้าเจอว่าไม่ใช่ ให้เพิ่มเงื่อนไขยกเว้น path นั้นออกจาก rule หรือใช้ 308 เฉพาะ path นั้นแทน 301

ทำไมเลือกให้ www เป็นตัวจริง ไม่ใช่ non-www

เพราะลิงก์ภายในของเว็บชี้ไป www อยู่แล้ว และฝั่ง www เสิร์ฟทุกพาธได้ถูกต้องอยู่แล้ว → เลือกทางนี้แล้วไม่ต้องแก้โค้ดแม้แต่บรรทัดเดียว ไม่ต้องรอคิวทีม System Development

และการลงทะเบียน AdSense ไว้เป็น gnjoy.in.th ยังใช้ได้ตามเดิม — Google ลงทะเบียนที่ระดับโดเมน ซึ่งครอบ www ให้อยู่แล้ว

วิธีแก้

  • ตัวแบ่งหน้าต้องเป็น <a href> จริง ที่มี URL ต่างกันต่อหน้า (/Events/Index/2) — ห้ามเป็นปุ่มที่เรียก JavaScript เท่านั้น
  • มีลิงก์ “ข่าวทั้งหมด” จากหน้าแรกไปหน้ารายการ และมีลิงก์กลับ
  • จัดหมวดข่าว ตามที่เกณฑ์ที่ 3 บอก — กิจกรรม · อัปเดตเกม · ประกาศ · แยกตามเกม แล้วให้แต่ละหมวดมีหน้าของตัวเองที่เดินเข้าไปได้
  • ตรวจเมนูบนมือถือ ว่ากดได้ครบทุกปุ่มและพาไปถูกหน้า — เกณฑ์ที่ 3 ระบุเรื่อง alignment · readability · functionality · accuracy ไว้ชัด
  • ไล่หาลิงก์เสีย ที่พาไปหน้า 404 หรือหน้าที่ไม่เกี่ยว — เกณฑ์ระบุว่าห้ามมี

ข้อนี้ไม่ต้องเขียนบทความใหม่แม้แต่ชิ้นเดียว — เนื้อหามีอยู่แล้ว แค่ทำให้เดินไปถึงได้ทั้งคนและเครื่อง

04

sitemap.xml — ส่งบัญชีรายชื่อหน้าให้ Google ตรง ๆ

ช่วยได้ ฝั่งเซิร์ฟเวอร์ ~2–4 ชม.

ทำไปทำไม

Google ค้นหน้าใหม่ด้วยวิธีเดียวคือเดินตามลิงก์ จากหน้าที่มันรู้จักอยู่แล้ว หน้าไหนไม่มีลิงก์ชี้ไปถึงเลยเรียกว่า orphan page — Google หาไม่เจอตลอดชีวิต แม้หน้านั้นจะเปิดได้ปกติเมื่อพิมพ์ URL เอง

sitemap เปลี่ยนจาก “ให้ Google เดินหาเอง” เป็น “เราส่งบัญชีรายชื่อให้ตรง ๆ” จึงเป็นตัวช่วยที่เร็วที่สุดของข้อ 03 ระหว่างที่งานปรับเมนูและตัวแบ่งหน้ายังไม่เสร็จ

ทำไมอยู่ชั้น “ช่วยได้” ไม่ใช่ “ต้องแก้” — เกณฑ์ทั้งสามข้อของ Google ไม่ได้พูดถึง sitemap เลย และไม่มี sitemap ก็ผ่านได้ แต่มันช่วยให้เนื้อหาที่มีอยู่ถูกนับเร็วขึ้นมาก

ไฟล์หน้าตาเป็นอย่างไร

ใช้แค่ 2 แท็ก — loc คือที่อยู่ · lastmod คือวันที่แก้ครั้งสุดท้าย

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://gnjoy.in.th/Events/EventDetail/563</loc>
    <lastmod>2026-09-01</lastmod>
  </url>
  <!-- วนทุกข่าวจาก DB -->
</urlset>

ส่วน priority กับ changefreq ที่เห็นในตัวอย่างตามเน็ต Google ประกาศแล้วว่าไม่สนใจ — ไม่ต้องใส่

โค้ด · สร้างจาก DB ไม่ใช่ไฟล์ที่แก้มือ

ถ้าทำเป็นไฟล์นิ่งจะต้องแก้ทุกครั้งที่ลงข่าว แล้วก็จะลืม

[Route("sitemap.xml")]
[ResponseCache(Duration = 3600)]            // cache 1 ชม. กันยิง DB ถี่
public IActionResult Sitemap()
{
    var news = _db.News.Where(n => n.IsPublished)
                       .OrderByDescending(n => n.UpdatedAt).ToList();

    var sb = new StringBuilder();
    sb.AppendLine(@"<?xml version=""1.0"" encoding=""UTF-8""?>");
    sb.AppendLine(@"<urlset xmlns=""http://www.sitemaps.org/schemas/sitemap/0.9"">");

    void Add(string path, DateTime mod) => sb.AppendLine(
        $"  <url><loc>https://gnjoy.in.th{path}</loc>" +
        $"<lastmod>{mod:yyyy-MM-dd}</lastmod></url>");

    Add("/",                DateTime.UtcNow);
    Add("/Game/GamePC",     new DateTime(2026, 8, 1));
    Add("/Game/GameMobile", new DateTime(2026, 8, 1));
    foreach (var n in news) Add($"/Events/EventDetail/{n.Id}", n.UpdatedAt);

    sb.AppendLine("</urlset>");
    return Content(sb.ToString(), "application/xml", Encoding.UTF8);
}

เอาไปใช้

  • เปิด https://gnjoy.in.th/sitemap.xml ได้ และมีข่าวทั้งคลัง
  • ส่งเข้า Search Console → Sitemaps → วาง URL → Submit

ได้อะไรกลับมา

ประโยชน์รายละเอียด
เนื้อหาถูกนับครบช่วยเกณฑ์ที่ 1 โดยไม่ต้องรอให้งานปรับเมนูเสร็จ
ข่าวใหม่เข้า index เร็วขึ้น ตรงกับธุรกิจเกมโดยตรง — ข่าวกิจกรรมมีอายุสั้น ถ้า Google เก็บช้าสองสัปดาห์ กิจกรรมจบไปแล้ว คนค้นเจอตอนหมดเวลา
ข่าวเก่าเข้า indexได้ traffic จากการค้นหาที่ตอนนี้ไม่ได้เลย เพราะ Google ไม่รู้ว่ามีอยู่
กลายเป็นเครื่องมือวัด Search Console จะรายงาน Discovered / Indexed — ตัวเลขนี้คือเครื่องวัดว่าปัญหาเนื้อหาไม่พอดีขึ้นจริงไหม และบอกว่าหน้าไหนติด 404 · redirect · noindex

ข้อควรระวัง

  • 🔴 URL ต้องเป็น https://www.gnjoy.in.th/… ให้ตรงกับข้อ 01 — เว็บใช้ www เป็นตัวหลัก ถ้าใส่แบบไม่มี www ทุก URL ใน sitemap จะกลายเป็น redirect ซึ่งผิดกติกาของ sitemap เอง
  • lastmod ต้องเป็นวันจริง จาก UpdatedAt — ถ้าใส่วันนี้ทุกหน้าทุกวัน Google จะเลิกเชื่อทั้งไฟล์
  • ห้ามใส่หน้าที่ 404 · redirect · noindex
  • จำกัด 50,000 URL ต่อไฟล์ — เกินต้องแตกหลายไฟล์ (เว็บนี้ยังไม่ใกล้)
  • โดเมนย่อยต้องมีไฟล์ของตัวเอง — ไฟล์ของ gnjoy.in.th ใส่ URL ของ event.gnjoy.in.th ไม่ได้ เพราะต่างโฮสต์กัน

sitemap ไม่ได้แทนอะไรบ้าง — ไม่การันตีว่า Google จะ index (แค่บอกว่ามีอยู่) · ไม่ช่วยอันดับโดยตรง · และไม่แทนข้อ 03 เพราะผู้ใช้จริงเดินตาม sitemap ไม่ได้ ยังต้องมีเมนูและตัวแบ่งหน้าที่ใช้งานได้อยู่ดี

🔎 ทำไมเปลี่ยนเป็น h1 แล้วฟอนต์เพี้ยน — สาเหตุคือ Bootstrap

ทีม System เคยลองแล้วพบว่าฟอนต์เพี้ยน เลยเลี่ยงไปใช้แท็กธรรมดา — เป็นการตัดสินใจที่ถูกต้องภายใต้ข้อมูลที่มีตอนนั้น และนี่คือสาเหตุที่แท้จริง

เว็บใช้ Bootstrap (เห็นจากคลาส breadcrumb-item · card-title) และ Bootstrap Reboot ตั้งขนาดฟอนต์ให้ h1–h6 ตามชื่อแท็ก 

h5 → 1.25rem = 20px   ← ขนาดที่เห็นอยู่ตอนนี้
h1 → 2.5rem  = 40px   ← พอเปลี่ยนแท็ก ขนาดกระโดดเป็นสองเท่าทันที

ตัวเลข 20px ที่เห็นอยู่ มาจากกฎ h5 ของ Bootstrap ไม่ได้มาจากคลาส .card-title — พอเปลี่ยนแท็กจึงเสียขนาดไปด้วย ไม่เกี่ยวกับ CMS และไม่เกี่ยวกับโค้ดที่ CMS เจนออกมา

โค้ด · h1 ที่ฟอนต์ไม่ขยับแม้แต่พิกเซลเดียว

/* pin ขนาดของ h1 ให้เท่ากับที่ h5 เป็นอยู่ทุกประการ
   ค่าทั้งหมดอ่านมาจากค่า computed จริงของหน้าเว็บ ไม่ได้ประมาณ */
h1.card-title{
  font-size:   1.25rem;   /* = 20px เท่าเดิม */
  font-weight: 500;       /* เท่าเดิม */
  line-height: 1.2;
  margin-bottom: .5rem;
}
<!-- เปลี่ยนแค่ชื่อแท็ก class เดิมทั้งหมด -->
<h1 class="card-title">@Model.Title</h1>

ถ้ายังไม่อยากเสี่ยง — ข้ามข้อนี้ได้

เกณฑ์ทั้งสามข้อของ Google ไม่ได้พูดถึง h1 เลยแม้แต่คำเดียว เว็บที่ไม่มี h1 ก็ผ่านการอนุมัติได้ — ข้อที่ต้องทำจริงคือเคส 02 (ยุบชื่อข่าวที่ซ้ำ 3 จุด) เท่านั้น

แต่ถ้าจะทำเคส 02 อยู่แล้ว ทำ h1 พ่วงไปเลยคุ้มกว่า เพราะแตะไฟล์เดียวกันและเพิ่ม CSS แค่ 4 บรรทัด

เรื่องที่ทีม System ไม่ต้องกังวล — หน้าข่าวมี element ที่ติด inline style อยู่ 190 จุด จากโค้ดที่ CMS เจนออกมา Google ไม่สนใจเรื่องนี้เลย ไม่มีเกณฑ์ข้อใดพูดถึงความสะอาดของ HTML สิ่งที่เป็นปัญหาคือชื่อข่าวซ้ำ อย่างเดียว

  • h1 1 ตัวต่อหน้า เท่านั้น — ไม่ใช่ 0 และไม่ใช่หลายตัว
  • ต้องเป็น ข้อความจริง ไม่ใช่รูปภาพ
  • ห้ามซ่อนด้วย display:none — ถ้าดีไซน์ไม่อยากให้เห็น ใช้คลาส sr-only
/* ใช้อันนี้ถ้าต้องซ่อน h1 ห้ามใช้ display:none */
.sr-only{
  position:absolute; width:1px; height:1px; padding:0; margin:-1px;
  overflow:hidden; clip:rect(0,0,0,0); white-space:nowrap; border:0;
}

อย่าแก้ ads.txt — ไฟล์ถูกต้องสมบูรณ์แล้ว ที่คอนโซลขึ้น Ads.txt: Not found เป็นเพราะ Google ยังไม่ได้เข้ามาเก็บข้อมูล ไม่ใช่เพราะไฟล์หาย เห็นคำนี้แล้วมักมีคนไปแก้ไฟล์ที่ถูกอยู่แล้วจนพัง
