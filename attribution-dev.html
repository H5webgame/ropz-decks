// server-side — game-scoped attribution (per user × game)
function attribute(session, user, gameId) {
  let source;
  if (session.ref && isValidPartnerRef(session.ref, gameId)) // ref signed for THIS game
      source = mapDevChannel(session.ref);              // #8-11
  else if (session.campaignId || isInternal(session.referrer))
      source = mapRopzChannel(session);                 // #1-5
  else
      source = "ROPZ_ORGANIC";                          // #6 default

  const key = user.id + ":" + gameId;                   // first-touch PER GAME
  if (!attribution[key]) {
      attribution[key] = { source,
        status: isDev(source) ? "PENDING" : "CONFIRMED" };
  }
  return attribution[key];        // dev-rate applies to THIS game only
}
// 5 games live → partner mints 5 signed links (partnerID + gameId + channel)

Quality User (Fraud Gate) — Dev-brought ต้องผ่านถึงจะ CONFIRMED (ภายใน 7 วัน)

ชั้น A — VALID (ไม่ผ่าน = ทิ้ง)

ผ่าน bot check · IP ไม่ใช่ datacenter/proxy · device fingerprint ไม่ซ้ำ

ชั้น B — QUALITY (ผ่าน ≥1)

เล่น ≥3 นาที (24ชม.แรก) · หรือ ≥2 sessions · หรือถึง milestone · หรือ D1 retention · หรือเป็น payer (auto)

State: PENDING → CONFIRMED (จ่ายเรต dev) / EXPIRED (ตกเป็น ROPZ) · velocity cap + right-to-audit · threshold = v1 default, pilot calibrate

6ความปลอดภัย & Anti-Fraud

ความปลอดภัย 2 ชั้น (Defense-in-Depth)

Edge กันทราฟฟิกร้ายก่อนถึงระบบ · App คัดคุณภาพ + คุมการจ่ายเงิน — 2 ชั้นทำงานซ้อนกัน

🌐 ชั้น Edge — Cloudflare

🛡️ ชั้น App — Attribution & Payout

12สรุปรวม · 4 แกน

อะไรบ้างที่กำหนดส่วนแบ่ง — และแกนไหนไม่เกี่ยว

คำว่า "Tier" ถูกใช้ 3 ความหมายในโปรเจกต์นี้ ตารางนี้แยกให้ชัดว่าแกนไหนขยับเงิน แกนไหนแค่จัดประเภท

แกนตอบคำถามอะไร ค่าที่เป็นไปได้กระทบส่วนแบ่งยังไง
① Attribution — ใครพาผู้เล่นมาผู้เล่นคนนี้เข้ามาจากช่องทางของใครROPZ พามา (default) · Dev พามา (verified + ผ่าน fraud gate)✅ ขยับ Platform Fee โดยตรง — ads 50/50 → 85/15 · IAP 60/35 → 75/20
② Asset Provenance — ใครลงแรงทำอาร์ตเกมนี้สร้างบน Base Asset Pack ของเรากี่ %< 20% · 20–60% · > 60% (ถ่วงน้ำหนักรายชิ้น)✅ ปรับ Platform Fee เพิ่ม +0 / +~5 / +~10 จุด (v0.1 รอเคาะ)
③ Tier A/B/C — เชื่อมเกมแบบไหนฝังพอร์ทัล / +Quest / Full game ผ่าน APIA · B · C (ระบุใน manifest.tier)❌ ไม่ขยับเรต — ต่างกันที่ economy ที่ผูกและเครื่องมือที่ได้
④ T0–T4 — ใช้ IP RO ลึกแค่ไหนเกมใช้ทรัพย์สินทางปัญญา RO ระดับไหนT0 – T4 (เฉพาะเกมที่ใช้ IP RO)✅ แต่เป็น ชั้นแยก (IP Royalty) ซ้อนบน — ไม่ใช่ Platform Fee

แล้วแกนไหนแตะรายได้ชั้นไหน

  • ชั้น 1 · Platform Fee — ขยับด้วย ① Attribution และ ② Asset Provenance
  • ชั้น 2 · IP Royalty — ขยับด้วย ④ T0–T4 เฉพาะเกมที่ใช้ IP RO
  • ชั้น 3 · Coupon / Ecosystem — ROPZ ล้วน ไม่มีแกนไหนมาขยับ
⚠️ จุดที่สับสนบ่อย: ③ Tier A/B/C · ④ T0–T4 · ② coverage เป็นคนละแกนกันหมด — มีแค่ ① กับ ② ที่ขยับ Platform Fee · ④ อยู่คนละชั้น · ③ ไม่ขยับเงินเลย
13แกน ② · Asset Provenance

Base Asset Pack + วิธีตรวจว่า build ใช้ของเรา

คลัง asset พร้อมใช้ ฟรี ให้ dev/outsource หยิบไปทำเกมได้อิสระ — ลดต้นทุนและเวลา พร้อมคุมคุณภาพ/ขนาดตั้งแต่ต้นทาง

ในแพ็กมีอะไร — เป้า 20–30 ชุดต่อประเภท

  • 🎨 Texture / ตัวละคร — sprite set · recolor-ready · pivot/footprint iso · atlas-friendly
  • 🎵 BGM — เพลงพื้นหลังแบบ loop
  • 🔊 SFX — เสียง action / UI
  • ✨ VFX — ปรับเบาสำหรับเว็บ (particle ต่ำ · texture เล็ก · ไม่กิน fps/memory)
ทุกชิ้น web-optimized มาแล้ว — texture crunch ≤1024 · audio Vorbis (เพลง 96–128kbps · SFX mono 22kHz) · VFX budget-capped → dev ใช้แล้วผ่าน size/quality gate เกือบชัวร์

Coverage → ส่วนแบ่ง

Coverageความหมายส่วนของ ROPZ
< 20%dev ทำอาร์ตเองเป็นหลักbaseline (dev เก็บมากสุด)
20–60%ผสม+~5 จุด
> 60%เกมสร้างบน asset เรา = เราร่วมผลิต+~10 จุด
Framing ที่ล็อกแล้ว — contribution-based ไม่ใช่บทลงโทษ: rev-share สะท้อนว่าใครลงแรงผลิต · เราออก asset ให้ = เราร่วมผลิต = แบ่งเรามากขึ้นนิด · dev เอาอาร์ตตัวเองมา = เก็บมากขึ้น · dev เลือกเองได้ว่าจะใช้แค่ไหน และ delta ตั้งใจให้โมเดสต์ เพื่อไม่ให้คนเลี่ยงใช้ pack

ตรวจยังไงว่า build ใช้ asset ของเราจริง — 3 ชั้น

ปัญหา: dev บีบ texture (crunch) หรือแปลง audio (Vorbis) → byte เปลี่ยน → เทียบ hash ตรง ๆ ใช้ไม่ได้

  • A · Build-time manifest (หลัก) — BuildProcessor สแกน project ตอน build ว่าอ้าง asset จาก pack (ดู GUID/path) → เขียน ropz_assets.json (assetId + coverage%) เซ็น HMAC ฝังใน build · ครอบคลุมทุกชนิดรวม VFX/prefab/particle
  • B · Server fingerprint (ตัวตรวจ) — ตอน gate แตก texture/audio จาก .data แล้วทำ perceptual hash (pHash ภาพ / audio fingerprint) เทียบ registry — ทนการบีบ/แปลงไฟล์ · ยืนยันว่า manifest ไม่โกหก
  • C · Registry — เก็บ {assetId, GUID, pHash/audioFP, type, weight} = single source of truth
กันโกง: manifest signed = ยกบาร์ · fingerprint = guard จริง · อ้าง manifest แต่ fingerprint ไม่ตรง → flag/reject · เจอทีหลัง = reactive audit + clawback (หลักการเดียวกับ attribution) · VFX ตรวจย้อนหลังยาก → พึ่งชั้น A เป็นหลัก
⚠️ ตัวเลข % จริงยังเป็น placeholder — รอเคาะเชิงธุรกิจ · modifier นี้อยู่บน Platform Fee เท่านั้น ไม่ยุ่ง T0–T4 (IP) และ L0–L2 (ต้นทุนของรางวัล)
