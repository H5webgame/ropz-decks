3. What the plugin gives you — one API, two transports

Source Integration Guide · 3. What the plugin gives you — one API, two transports

Your game code always calls one interface: RouBootstrap.Client, of type IRouClient. It never needs to know what sits behind it, and there is no switch to set — the choice is structural:

When Transport Talks to
Editor play mode DirectHttp (UnityWebRequest) the local mock gateway, or the sandbox
Every player build Bridge (postMessage) the portal page hosting your game in an <iframe>

Why it can decide for itself: the DirectHttp assembly is Editor-only, so it does not exist in a player build. There is no way to accidentally ship a game that calls the gateway over HTTP directly.

What your build does not hold: the game key, any token, any backend URL, and not even the game id. All of it lives on the portal side, which signs and performs the real HTTP call. Your game only sends an action name plus a payload. (The game id you actually need comes back from init — see §5.)

Shipped Config — travels inside your build

Setting What to set it to

What Portal Origins is, and why you do not fill it in — it is the allowlist the bridge's JavaScript side checks event.origin against on every message. The plugin ships the platform team's canonical list of 8, taken from their unity/BRIDGE.md:

https://rou-dev.gnjoy.in.th      https://ropz-dev.gnjoy.in.th
https://rou-uat.gnjoy.in.th      https://ropz-uat.gnjoy.in.th
https://rou.gnjoy.in.th          https://ropz.gnjoy.in.th
http://localhost:4000            ← the portal running locally (npm run dev)
http://localhost:8787            ← the portal harness in DevTools/

The rules that matter:

  • Never guess a hostname and add it. Earlier builds carried rou-game-*.gnjoy.in.th, which does not exist. A non-existent host breaks nothing (it can never send rou:ready) but it teaches the next reader that the host is real. If you genuinely need a new origin, confirm it with the Web team first.
  • ropz-game-* is where the game itself is served from. It is not a portal origin and does not belong in this list.
  • The two localhost entries sit last so a production build can trim the tail.
  • Never "*" — the build processor fails the build, and the bridge already fails closed: an origin that does not match means every message is dropped silently, inbound and outbound.
  • If your project already stored an older list, opening the Editor removes the phantom hosts for you. It only ever removes — it never adds anything, because silently widening someone's origin allowlist is not a migration's decision to make.

Dev / Sandbox Config — never ships, used only for testing in the Editor

Setting What it does
API Base URL Where test calls go, e.g. http://localhost:4010/game/v1
Game Id / Game Key Sent as the X-Game-Id / X-Game-Key headers while testing. The gateway validates them as a pair.
Session Mode ticket (spends one ticket per round) or free (spends nothing, but the score and the player's personal best are still recorded)

In production the portal chooses the session mode, not the game, so this setting only affects the Editor. Read the value the server actually confirmed from Session.Mode on the start result.

Two guards run at build time: if the Dev Config ends up in Preloaded Assets, or Portal Origins contains "*", the build fails and tells you why. An empty allowlist produces a warning.

    // Editor = DirectHttp เข้า mock/sandbox, player build = bridge ผ่าน portal)

5. Calling it from your game

Source Integration Guide · 5. Calling it from your game

Wait for boot, then hold the one client. No call throws for a gateway error — every result comes back as a RouResult<T>, so always check IsSuccess.

using Cysharp.Threading.Tasks;
using GravityGameTech.WebGameStarter.Bootstrap;
using GravityGameTech.WebGameStarter.Shared;
using RoUniversal.GameApi;
using UnityEngine;

public sealed class GameFlow : MonoBehaviour
{
    private void Start()
    {
        if (RouBootstrap.IsReady) OnReady();
        else RouBootstrap.OnBootCompleted += OnReady;
    }

    private void OnReady()
    {
        // The game id every endpoint needs comes from the init result, not from your config.
        string gameId = RouBootstrap.InitResult.Data.Game.GameId;
        PlayOneRound(gameId).Forget();
    }

    private async UniTaskVoid PlayOneRound(string gameId)
    {
        var ct = this.GetCancellationTokenOnDestroy();

        RouResult<Session> start = await RouBootstrap.Client.StartSessionAsync(ct);
        if (!start.IsSuccess)
        {
            ShowMessage(start.Error);   // not enough tickets, login expired, and so on
            return;
        }

        string sessionId = start.Data.SessionId;
        string nonce = start.Data.Nonce;      // anti-replay; hand it back on finish

        // ...play the round, sending heartbeats as you go (see §5.1)...

        RouResult<RewardResult> finish = await RouBootstrap.Client.FinishAsync(
            sessionId, new FinishSessionRequest { Score = 1000, Nonce = nonce }, ct);

        if (finish.IsSuccess)
        {
            // A reward trimmed by a cap is still a SUCCESS, not an error.
            ShowReward(finish.Data);
        }
    }
}

Everything you can call (per-endpoint detail lives in ROU-API-Usage):

Method What it does
InitAsync Free boot handshake — player, wallet, Game.GameId, CanStart. RouBootstrap already calls it.
StartSessionAsync Opens a round, returns SessionId + Nonce
ProgressAsync In-round heartbeat
FinishAsync Submit the score, receive the reward. Sending the same score again is safe — the result does not change.
GetCurrencyAsync Read the wallet
GetLeaderboardAsync Top scores; page on with the previous page's nextPageToken
LoadSaveAsync / WriteSaveAsync One save blob, up to 32 KB. Writing blob: null deliberately clears the save.
GetMasterdataAsync Version-keyed master data — prefer RouMasterData.GetOrFetchAsync<T>(), which caches for you

5.1 Progress — the in-round heartbeat

The gateway judges a round from this series of heartbeats, and it measures how complete the series is against its own clock, at roughly one per 10 seconds. A round that sends too few can come back with no verdict. So send on real elapsed time, not per frame — and never let a failure here interrupt play: if a heartbeat does not land, keep playing.

private async UniTaskVoid SnapLoop(string sessionId, CancellationToken ct)
{
    while (!ct.IsCancellationRequested)
    {
        await UniTask.Delay(TimeSpan.FromSeconds(10), ignoreTimeScale: true, cancellationToken: ct);

        var snap = new ProgressEvent
        {
            Kind  = "snap",
            At    = DateTime.UtcNow.ToString("o"),   // RFC3339
            Value = _score,                          // a number is safe in every environment
        };

        // Don't check the result, don't retry — if it fails, the round carries on.
        await RouBootstrap.Client.ProgressAsync(sessionId, snap, ct);
    }
}

ProgressEvent.Value accepts two shapes: a number (read as the score), or a flat map of numbers, which is what lets a scoring rule refer to a counter by name:

Value = new Dictionary<string, double>
{
    { "score",   _score   },
    { "correct", _correct },
    { "combo",   _combo   },
},

A nested map, an array, or a string is rejected with 422.

For now, send a number if the build is going to uat or production. The map form needs a newer gateway that is currently deployed to dev only.

5.3 Saves — one blob, 32 KB max

// Write: pass your own class straight in, Newtonsoft serializes it.
var payload = new MySave { Level = 7, Coins = 120 };
RouResult<SaveBlob> written = await RouBootstrap.Client.WriteSaveAsync(
    gameId, new SaveBlobWrite { Blob = payload }, ct);

// Read: Blob is a JToken, and it is null when nothing has been saved yet.
RouResult<SaveBlob> loaded = await RouBootstrap.Client.LoadSaveAsync(gameId, ct);
if (loaded.IsSuccess && loaded.Data.Blob != null)
{
    MySave save = loaded.Data.Blob.ToObject<MySave>();
}

// Clear the save: a null blob is the instruction "clear it", not "I sent nothing".
await RouBootstrap.Client.WriteSaveAsync(gameId, new SaveBlobWrite { Blob = null }, ct);

5.4 Master data

Declare a class matching your game's shape and go through RouMasterData — it caches by version, so a second call in the same session touches no network, and it re-fetches on its own once ops bump the version.

RouResult<MyMasterData> md = await RouMasterData.GetOrFetchAsync<MyMasterData>(ct);
if (md.IsSuccess)
{
    ApplyTuning(md.Data.MaxScorePerHop);

private CancellationTokenSource _snapCts;

private void StartSnapLoop()                       // เรียกหลัง StartSessionAsync สำเร็จ
{
    _snapCts = CancellationTokenSource.CreateLinkedTokenSource(_ct);
    SnapLoopAsync(_openSession.SessionId, _snapCts.Token).Forget();
}

private void StopSnapLoop()                        // เรียกก่อน FinishAsync (และใน OnDisable)
{
    _snapCts?.Cancel();
    _snapCts?.Dispose();
    _snapCts = null;
}

private async UniTaskVoid SnapLoopAsync(string sessionId, CancellationToken ct)
{
    try
    {
        while (!ct.IsCancellationRequested)
        {
            // ignoreTimeScale: true — timeScale = 0 ตอน pause ไม่ควรทำให้ heartbeat หยุดเดิน
            await UniTask.Delay(TimeSpan.FromSeconds(10), ignoreTimeScale: true, cancellationToken: ct);

            var snap = new ProgressEvent { Kind = "snap", At = NowRfc3339(), Value = CurrentTotals() };
            RouResult<Ack> r = await RouBootstrap.Client.ProgressAsync(sessionId, snap, ct);

            // ล้มเหลวก็แค่ log — ห้าม return/throw ออกจาก loop เพราะ snap ที่หายไปทำให้ coverage ตก
            if (!r.IsSuccess) Debug.LogWarning($"[snap] {r.Error.Code} · {r.Error.Message}");
        }
    }
    catch (OperationCanceledException) { /* จบรอบ หรือ object ถูกทำลาย — ปกติ */ }
}

private Dictionary<string, double> CurrentTotals() => new Dictionary<string, double>
{
    { "score", _score }, { "correct", _correctHits }, { "empty", _emptyTaps },
};

ชื่อ key ควรใช้ ชุดเดียวกับที่ส่งตอน finish — correct ใน window กับ correct ทั้งรันคือ counter ตัวเดียวกันที่อ่าน 2 จังหวะ ถ้าตั้งชื่อไม่ตรงกัน event contract ต้องประกาศ 2 สะกดโดยไม่มีเหตุผล

8. Reading results correctly

Source Integration Guide · 8. Reading results correctly

No call throws for a gateway error. Everything arrives in RouResult<T>:

if (!result.IsSuccess)
{
    RouFailure e = result.Error;
    // e.Code       e.g. "TICKET_INSUFFICIENT" — branch on this, never on the HTTP status
    // e.Audience   "player" | "developer" | "ops"
    // e.HttpStatus / e.Retryable
}

Audience is the rule for where a message may appear. "player" may go on screen. "developer" and "ops" must never reach a player — log them and show something generic instead. For a code you do not recognise, decide from Audience, never by guessing from the name.

Retries are already handled for you: 401 is never retried (it is a token problem); a transport failure, 429, or 503 backs off and retries at 500/1000/2000 ms for at most 3 attempts; other 4xx and any 5xx that is not 503 are not retried. Your job is to handle the final outcome — do not wrap another retry loop around it.

Cases you definitely have to handle: not enough tickets at start; RouSdkBridge.OnAuthExpired (the portal session died — call RouBootstrap.InitializeAsync() again and do not blind-retry the original request); and a finish whose reward was trimmed by a cap, which counts as success.

6. Error & Result Semantics

Source Architecture · 6. Error & Result Semantics

  • ทุก call คืน RouResult<T> — IsSuccess/Data/Error(RouFailure) ไม่ throw ข้าม boundary
  • Switch ด้วย RouFailure.Code (stable string) ไม่ใช่ HTTP status
  • capped ตอน finish = success (RewardResult.Capped == true) — ห้าม treat เป็น error
  • Bridge-side codes เพิ่มเติม: BRIDGE_NOT_AVAILABLE (เรียกนอก portal build), transport failure จาก timeout/not-ready; ชั้น typed masterdata มี MASTERDATA_PARSE_ERROR (payload ไม่ตรง class)
  • error.requestId (จาก gateway ผ่าน SDK) ใช้ trace กับทีม platform ได้

2.1.2 Wire contract

Envelope (คงที่ทุก action):

// game → portal
{ "v": 1, "type": "rou:req", "requestId": "<guid-N>", "action": "<name>", "payload": { } }
// portal → game (หนึ่ง res ต่อหนึ่ง req เสมอ, จับคู่ด้วย requestId)
{ "v": 1, "type": "rou:res", "requestId": "...", "ok": true,  "data": { } }
{ "v": 1, "type": "rou:res", "requestId": "...", "ok": false, "error": { "code", "status", "retryable", "requestId?" } }
Action Payload หมายเหตุ
session.init {} boot ฟรี — ได้ player/wallet/canStart (token ถูก strip)
session.start {} หัก ticket, เปิด session (ได้ sessionId + nonce)
session.progress {sessionId, ev} event ระหว่างเล่น (optional)
session.finish {sessionId, body:{score, nonce, clientHash?}} nonce = anti-replay จาก start; capped = success (RewardResult.Capped)
currency.get {} อ่าน wallet
leaderboard.get {gameId, limit?, pageToken?} gameId = ค่าของ gateway จาก init result (GameContext.Game.GameId) ไม่ใช่ค่าใน config
save.load / save.write {gameId} / {gameId, body} blob:null ใน write = ตั้งใจล้าง save
