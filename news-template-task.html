ข่าวดี — ทั้งสามงานแตะที่เดียวกัน คือ template และ CSS ของหน้าข่าว ทำรอบเดียวจบ และมีผลย้อนหลังกับข่าวทั้งคลัง 400–580 บทความ โดยไม่ต้องไปแก้ข่าวทีละชิ้น

01

ยุบชื่อข่าวที่ซ้ำ 3 จุด ให้เหลือจุดเดียว

ต้องทำ View หน้าข่าว ~1 ชม.

หลักฐาน — อ่านจาก DOM จริง ไม่ได้ประมาณ

ชื่อข่าวเดียวกันปรากฏบนหน้าเดียว 5 ครั้ง โดย 3 ครั้งมาจาก template

Elementขนาดที่เรนเดอร์จริงทำอย่างไร
LI.breadcrumb-item active 14px / 300 / Kanit เก็บไว้ เป็น breadcrumb ที่ถูกต้อง
P.txt-head 24px / 400 / Kanit เลือกเก็บ 1 ลบ 2
สามจุดนี้คือชื่อข่าวเดียวกันทั้งหมด เลือกเก็บตัวที่ดีไซน์ต้องการ ที่เหลือลบทิ้ง
H5.card-title 20px / 500 / Kanit
P.txt-title 16px / 400 / Kanit
SPAN ในเนื้อหา 12px / 500 / Noto Sans Thai งานคอนเทนต์ คนลงข่าวพิมพ์ชื่อซ้ำในช่องเนื้อหา ไม่ใช่โค้ด

เป็น template จึงเกิดกับทุกข่าวในเว็บ ไม่ใช่แค่ข่าวเดียว — คลังข่าวมีประมาณ 400–580 บทความ ทุกบทความมีอาการนี้เหมือนกันหมด

ทำไมต้องแก้

Google เขียนเกณฑ์ไว้ตรงตัวว่า “ensure that the same content is not duplicated in the same page” และ “try to minimize repeating long segments of text”

เว็บกำลังรอผลตรวจเพื่อเปิดใช้โฆษณา และเกณฑ์ข้อนี้คือข้อที่เว็บสุ่มเสี่ยงจะตกมากที่สุด

สิ่งที่ต้องทำ

  • เปิด View ของหน้าข่าว หา 3 element ในตาราง → เก็บไว้ตัวเดียว ลบอีกสองตัว
  • ถ้าสามจุดดึงมาจากคนละฟิลด์ (Title · SubTitle · ShortTitle) แล้วคนลงข่าวกรอกเหมือนกันหมด → แก้ที่เครื่องมือเขียนข่าว ให้ยุบฟิลด์ที่ไม่ได้ใช้จริง หรือเตือนเมื่อกรอกซ้ำ
  • ถ้า layout พังเพราะลบ element ออก ให้ย้าย class ของ element ที่ลบไปไว้ที่ตัวที่เก็บ แทนการเก็บทั้งสามตัวไว้แล้วซ่อนด้วย CSS

⚠️ ห้ามแก้ด้วยการซ่อน — ใช้ display:none หรือ visibility:hidden กับ element ที่ซ้ำ ไม่ช่วย เพราะข้อความยังอยู่ใน HTML ที่ Google อ่าน ต้องลบออกจากผลลัพธ์จริง

ตรวจว่าเสร็จ

เปิดหน้าข่าวแล้ววางใน Console — ต้องได้ 2 (breadcrumb 1 + หัวเรื่อง 1)

// นับว่าชื่อข่าวโผล่กี่ครั้งในหน้า
[...document.querySelectorAll('body *')].filter(e =>
  [...e.childNodes].filter(n => n.nodeType === 3)
    .map(n => n.textContent).join('')
    .includes('ใส่ชื่อข่าวตรงนี้')
).length
02

ทำจุดที่เหลือให้เป็น h1 — พร้อมวิธีที่ฟอนต์ไม่เพี้ยน

ทางเลือก +CSS 4 บรรทัด ~15 นาที

ทีมเคยลองแล้วฟอนต์เพี้ยน เลยเลี่ยงไปใช้แท็กธรรมดา — เป็นการตัดสินใจที่ถูกต้อง ภายใต้ข้อมูลที่มีตอนนั้น และนี่คือสาเหตุที่แท้จริง

สาเหตุคือ Bootstrap ไม่ใช่ CMS

เว็บใช้ Bootstrap (เห็นจากคลาส breadcrumb-item · card-title) และ Bootstrap Reboot ตั้งขนาดฟอนต์ให้ h1–h6 ตามชื่อแท็ก 

h5 → 1.25rem = 20px   ← ขนาดที่เห็นอยู่ตอนนี้
h1 → 2.5rem  = 40px   ← พอเปลี่ยนแท็ก ขนาดกระโดดเป็นสองเท่า

ตัวเลข 20px ที่เห็นอยู่ มาจากกฎ h5 ของ Bootstrap ไม่ได้มาจากคลาส .card-title พอเปลี่ยนแท็กจึงเสียขนาดไปด้วย

วิธีที่ฟอนต์ไม่ขยับแม้แต่พิกเซลเดียว

/* pin ขนาดของ h1 ให้เท่ากับที่ h5 เป็นอยู่ทุกประการ
   ค่าทั้งหมดอ่านมาจาก computed style จริงของหน้าเว็บ */
h1.card-title{
  font-size:     1.25rem;   /* = 20px เท่าเดิม */
  font-weight:   500;       /* เท่าเดิม */
  line-height:   1.2;
  margin-bottom: .5rem;
}
<!-- เปลี่ยนแค่ชื่อแท็ก class เดิมทั้งหมด -->
<h1 class="card-title">@Model.Title</h1>

ถ้าเลือกเก็บ P.txt-head หรือ P.txt-title ไว้แทน ให้เปลี่ยนชื่อคลาสในกฎ CSS ข้างบนตาม แล้วปรับ font-size เป็น 24px หรือ 16px ให้ตรงกับของเดิม

โครงหัวข้อปัจจุบัน — เหลือขาดแค่ H1

ส่วนที่เหลือของหน้าถูกต้องอยู่แล้ว ไม่ต้องแตะ

h1  — ไม่มี — ← จุดเดียวที่ขาด
h5  ชื่อข่าว (.card-title)
h2  Ragnarok : The Promised Adventure
h2  กำหนดการ Pre-CBT
h3  MVP Boss
h3  Poring Island Challenge
h4  Relate News

ถ้าประเมินแล้วยังเสี่ยง — ข้ามข้อนี้ได้เลย

เกณฑ์ของ Google ไม่ได้พูดถึง h1 เลยแม้แต่คำเดียว เว็บที่ไม่มี h1 ก็ผ่านการอนุมัติได้ — ข้อ 01 เป็นข้อเดียวที่จำเป็นจริง

เหตุผลเดียวที่เสนอให้ทำพ่วงคือมันแตะไฟล์เดียวกันกับข้อ 01 จึงประหยัดรอบ deploy

ตรวจว่าเสร็จ

document.querySelectorAll('h1').length   // ต้องได้ 1
getComputedStyle(document.querySelector('h1')).fontSize
// ต้องได้ค่าเดิมก่อนแก้ เช่น "20px"
03

เนื้อหาข่าวพังบนมือถือ — เป็นผลข้างเคียงจากการก๊อปวาง

ต้องทำ CSS ของ template ~2 ชม. แก้ครั้งเดียวได้ทุกข่าว

โค้ดแปลก ๆ นั้นคืออะไร — ระบุได้แล้ว

ไม่ใช่ CMS เจนเอง แต่เป็นร่องรอยการก๊อปเนื้อหามาจาก Google Docs แล้ววางลงในเครื่องมือเขียนข่าว ตัวแก้ไขจึงเก็บ inline style ของ Google Docs มาทั้งชุด

inline style ที่พบจำนวนแปลว่า
font-family:'Noto Sans Thai',sans-serif95ฟอนต์เริ่มต้นของ Google Docs
color:#00000092สีดำตายตัว
font-size:9pt88= 12px — ต้นเหตุของปัญหา
color:#1155cc3สีลิงก์ของ Google Docs
<font color=#ababab>8แท็กที่เลิกใช้แล้ว อยู่ที่ footer

ไม่พบร่องรอยของ Microsoft Word เลย (mso- · <o:p> · MsoNormal = 0) จึงยืนยันได้ว่ามาจาก Google Docs

🔴 ผลข้างเคียงสองอย่างที่เป็นปัญหาจริง

ตัวความรกไม่ใช่ปัญหา แต่สองอย่างนี้ชนเกณฑ์ของ Google ตรง ๆ

อาการวัดได้เท่าไรชนเกณฑ์ข้อไหน
ตัวหนังสือเนื้อหาข่าวเล็กเกินไป 12px
ทั้งบนเดสก์ท็อปและมือถือ		 “Readability — Is the text content on your site easy to read?”
หน้าเลื่อนแนวนอนได้บนมือถือ ล้นออกไป 303px
บนจอกว้าง 375px		 “Alignment — Are all the navigational elements lined up correctly across all devices?”

ทดสอบด้วยการจำลองจอมือถือ 375×812 แล้ววัดจากหน้าจริง — ตัวที่ล้นออกนอกจอคือ SPAN และ IMG ในเนื้อหาข่าว

วิธีแก้ — CSS ชั้นเดียว ไม่ต้องไล่แก้ข่าวเก่า 400 กว่าชิ้น

inline style ชนะ stylesheet ปกติ จึงต้องใช้ !important ทับ ใส่ครั้งเดียวที่ template มีผลย้อนหลังกับทุกข่าวที่ลงไปแล้ว 

/* เปลี่ยน .news-body เป็นคลาสของกล่องเนื้อหาข่าวจริง */
.news-body{
  font-size: 16px;
  line-height: 1.75;
  overflow-wrap: anywhere;
}

/* ล้าง inline style ที่ติดมาจากการวาง — เว้น h2/h3/h4 ไว้ให้มีขนาดของตัวเอง */
.news-body span,
.news-body p,
.news-body div,
.news-body li{
  font-size:   inherit !important;
  font-family: inherit !important;
  color:       inherit !important;
}

/* กันรูปและตารางล้นจอมือถือ */
.news-body img,
.news-body table,
.news-body iframe{
  max-width: 100% !important;
  height:    auto !important;
}

ต้องทดสอบก่อนขึ้นจริง — ถ้าข่าวเก่าบางชิ้นตั้งใจใช้สีหรือขนาดพิเศษ กฎนี้จะล้างทิ้งไปด้วย ลองกับข่าวสัก 5–10 ชิ้นที่หน้าตาต่างกันก่อน ถ้าเจอปัญหา ให้ตัด color: inherit ออกก่อนเป็นอย่างแรก

แก้ที่ต้นทางด้วย — ไม่ให้เกิดซ้ำ

  • ตั้งค่าเครื่องมือเขียนข่าวให้ ล้าง format ตอนวาง (paste as plain text) — ตัวแก้ไขข้อความส่วนใหญ่มีตัวเลือกนี้อยู่แล้ว
  • หรือใส่ตัวกรองฝั่งเซิร์ฟเวอร์ ตัด attribute style ออกตอนบันทึกข่าว
  • แจ้งทีมคอนเทนต์ว่าให้วางแบบไม่มีรูปแบบ (Ctrl+Shift+V) เวลาก๊อปจาก Google Docs

ตรวจว่าเสร็จ

// เปิดหน้าข่าวบนมือถือหรือย่อจอเหลือ 375px แล้ววางใน Console
document.documentElement.scrollWidth - document.documentElement.clientWidth
// ต้องได้ 0 (ตอนนี้ได้ 303)

getComputedStyle(document.querySelector('.news-body span')).fontSize
// ต้องได้ "16px" (ตอนนี้ได้ "12px")
